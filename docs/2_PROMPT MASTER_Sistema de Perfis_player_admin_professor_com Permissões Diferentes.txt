Você agora é um desenvolvedor fullstack especializado em autenticação e controle de acesso (RBAC – Role-Based Access Control).

Quero que você crie um **sistema de perfis (roles)** com permissões diferentes para um projeto de jogo educacional chamado **Lutaver**.

======================================================================
🧱 1. STACK E ARQUITETURA
======================================================================

Use este stack (pode adaptar detalhes se necessário, mas mantenha a ideia):

- Backend: Node.js + Express
- View engine: EJS
- Banco de dados: MySQL
- ORM: Sequelize
- Sessão: express-session
- Arquitetura: MVC (models, controllers, routes, views)

Regras de idioma:
- Código (files, models, controllers, variáveis) em INGLÊS
- Interface do usuário (telas, labels, mensagens) em PORTUGUÊS do Brasil

Assuma que já existe:
- Model `User` com campo `role` (string)

======================================================================
👥 2. PERFIS (ROLES) DO SISTEMA
======================================================================

Quero três perfis básicos:

1. **admin**
   - Acesso total ao sistema
   - Pode gerenciar usuários, disciplinas, aventuras, cenas, questões, etc.

2. **teacher** (professor)
   - Pode:
     - ver lista de alunos/players (sem acesso total de usuário)
     - criar e gerenciar questões (questions)
     - criar e gerenciar aventuras (adventures) ligadas às suas disciplinas
     - ver resultados de quizzes dos alunos
   - NÃO pode:
     - gerenciar outros admins
     - deletar tudo no sistema (limitações em relação ao admin)

3. **player** (aluno)
   - Pode:
     - jogar o quiz
     - ver seu próprio personagem
     - ver suas aventuras, progresso, XP, afinidades, etc.
   - NÃO pode:
     - acessar CRUD de usuários
     - acessar painel administrativo
     - cadastrar novas disciplinas, aventuras globais, etc.

======================================================================
🔐 3. SISTEMA DE AUTORIZAÇÃO (MIDDLEWARES)
======================================================================

Crie middlewares para controlar acesso:

1. `authMiddleware`
   - Verifica se o usuário está logado (existe `req.session.user`)
   - Se não estiver logado → redirecionar para `/login`

2. `roleMiddleware` ou middlewares específicos
   Sugestão A (genérico):
   - Um middleware `roleMiddleware(requiredRoles)` que recebe uma lista de roles permitidos.
   - Exemplo: `roleMiddleware(['admin'])`, `roleMiddleware(['admin', 'teacher'])`
   - Se o usuário logado NÃO tiver um dos perfis da lista → retornar 403 ou redirecionar para página "Acesso negado".

   Sugestão B (específicos, se preferir):
   - `adminOnlyMiddleware`
   - `teacherOrAdminMiddleware`
   - `playerOnlyMiddleware`

Quero que você implemente **pelo menos uma solução** de middleware para roles (pode ser a A ou a B, você escolhe, mas explique qual usou).

Crie exemplos práticos de rotas com proteção:

1. Rotas administrativas (apenas admin)
   - `/admin/dashboard`
   - `/users` (CRUD de usuários)

2. Rotas de professor (teacher + admin)

3. Rotas de jogador (player + teacher + admin – qualquer logado)

   - `/characters/me`
   - `/play/quiz/:adventureId`
   - `/profile`

Peço que você:

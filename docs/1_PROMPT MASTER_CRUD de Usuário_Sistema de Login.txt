Você agora é um desenvolvedor fullstack especializado em sistemas web com autenticação.

Quero que você crie a estrutura COMPLETA de:

1. CRUD de USUÁRIOS
2. Sistema de LOGIN / LOGOUT / AUTENTICAÇÃO

para um projeto de jogo educacional chamado **Lutaver**.

======================================================================
🧱 1. STACK E ARQUITETURA
======================================================================

Use este stack (pode adaptar detalhes, mas mantendo a ideia):

- Backend: Node.js + Express
- View engine: EJS
- Banco de dados: MySQL
- ORM: Sequelize
- Arquitetura: MVC (models, controllers, routes, views)
- Sessões: express-session (ou similar)
- Criptografia de senha: bcrypt (ou bcryptjs)

Regra de idioma:
- Código (models, controllers, routes, variáveis) em INGLÊS
- Interface (labels, textos, botões) em PORTUGUÊS do Brasil

======================================================================
👤 2. MODEL USER (TABELA users)
======================================================================

Crie o model `User` com estes campos:

- id: INTEGER, PK, auto-increment
- name: STRING — nome completo do usuário
- email: STRING — único (unique)
- password_hash: STRING — senha criptografada (NUNCA guardar senha em texto puro)
- role: STRING — papel do usuário (ex: "player", "admin", "teacher")
- is_active: BOOLEAN — se o usuário está ativo
- created_at, updated_at (padrão Sequelize)

Regra:
- Não armazenar senha em texto plano.
- A senha deve ser recebida em texto plano no cadastro, mas convertida para `password_hash` com bcrypt.

======================================================================
🧩 3. FUNCIONALIDADES DE CRUD DE USUÁRIO
======================================================================

1. Listar usuários
   - Rota: GET `/users`
   - Mostrar: id, nome, email, role, status (ativo/inativo)
   - Botões: Editar, Desativar/Ativar, Excluir (se fizer sentido)

2. Criar usuário (via painel administrativo)
   - Rota: GET `/users/new`
   - Formulário com:
     - Nome
     - E-mail
     - Senha
     - Confirmação de senha
     - Papel (select: player, admin, teacher)
     - Ativo? (checkbox)
   - Rota: POST `/users`
   - Validar:
     - e-mail único
     - senha = confirmação
   - Criptografar senha antes de salvar (`password_hash`)

3. Editar usuário
   - Rota: GET `/users/:id/edit`
   - Pode alterar:
     - nome
     - email
     - role
     - is_active
   - Rota: POST/PUT `/users/:id`
   - Se for permitir troca de senha aqui, deixar claro no form.

4. Excluir usuário
   - Rota: POST/DELETE `/users/:id/delete`
   - Pode comentar que em produção é melhor só desativar (`is_active` = false).

5. Visualizar perfil individual (opcional)
   - Rota: GET `/users/:id`
   - Mostrar ficha básica do usuário.

======================================================================
🔐 4. SISTEMA DE LOGIN / LOGOUT / AUTENTICAÇÃO
======================================================================

Quero:

1. Tela de Login
   - Rota: GET `/login`
   - Formulário:
     - E-mail
     - Senha
     - (opcional) “Lembrar-me”
   - Interface em PT-BR, com mensagens amigáveis.

2. Processar Login
   - Rota: POST `/login`
   - Fluxo:
     - Buscar usuário por e-mail.
     - Verificar se é ativo.
     - Comparar senha enviada com `password_hash` via bcrypt.
     - Se falhar → voltar para `/login` com mensagem de erro (ex: "E-mail ou senha inválidos").
     - Se sucesso → salvar dados na sessão (ex: `req.session.user = { id, name, role }`).

3. Logout
   - Rota: POST ou GET `/logout`
   - Destruir a sessão e redirecionar para `/login`.

4. Middleware de autenticação
   - Um middleware `authMiddleware` que:
     - verifica se `req.session.user` existe;
     - se não existir, redireciona para `/login`.
   - Um middleware `adminMiddleware` que:
     - verifica se usuário logado possui `role = 'admin'`;
     - caso contrário, redireciona para uma página de acesso negado.

5. Proteção de rotas
   - Rotas como `/users`, `/users/new`, etc. devem ser acessíveis apenas por admin.
   - Rotas de jogo (ex: `/play`, `/characters`) podem exigir apenas usuário logado.

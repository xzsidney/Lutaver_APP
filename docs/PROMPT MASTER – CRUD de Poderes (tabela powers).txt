- createdAt        (DATETIME)
- updatedAt        (DATETIME)

Crie o **model Sequelize** `Power` se ainda não existir, com essas colunas e associação:

📂 ESTRUTURA QUE QUERO
====================================================================

Quero que você crie:

1. **Model**: `models/Power.js`
2. **Controller**: `controllers/powerController.js`
3. **Routes**: `routes/powerRoutes.js`
4. **Views EJS** (apenas admin):
   - `views/admin/powers/index.ejs`   → listagem de poderes
   - `views/admin/powers/form.ejs`    → criação/edição
   - (opcional) `views/admin/powers/show.ejs` → detalhes

As rotas devem seguir padrão REST:

- GET    `/admin/powers`           → listar poderes
- GET    `/admin/powers/new`       → formulário de criação
- POST   `/admin/powers`           → salvar novo poder
- GET    `/admin/powers/:id/edit`  → editar poder
- POST/PUT `/admin/powers/:id`     → atualizar poder
- POST/DELETE `/admin/powers/:id/delete` → excluir poder

Considere que **a área admin é autenticada** e só usuários com role `admin` (ou `teacher`, se eu decidir depois) podem acessar.

====================================================================
🧪 REGRAS DE NEGÓCIO DO PODER
====================================================================

Validações:
- `name`: obrigatório, único dentro da disciplina
- `discipline_id`: obrigatório, deve existir na tabela disciplines
- `required_affinity`: obrigatório, número inteiro entre 0 e 100
- `description`: obrigatório, texto amigável explicando o poder
- `effect`: obrigatório, explicando mecanicamente o impacto (ex.: “+2 em Inteligência em quizzes de Matemática”)
- `icon`: opcional, mas recomendável (emoji ou nome de ícone)

Regra de afinidade (conceitual):
- Só personagens com afinidade naquela disciplina **>= required_affinity** poderão aprender esse poder.
(Não precisa implementar essa lógica agora, mas deixe o campo bem preparado.)
